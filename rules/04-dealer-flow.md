# 四、庄家流程

## 4.1 拿底牌

1. **收取底牌**：庄家收取 7 张底牌（庄家手牌从31张变为38张）
2. **整理手牌**：将底牌与手牌合并整理

## 4.2 扣底牌

1. **扣回底牌**：庄家选择 7 张牌扣回底牌（面朝下，不公开）
2. **扣牌规则**：随意扣牌，不做任何限制（可以扣主牌、分牌等任意牌）
3. **扣牌后**：庄家手牌从38张变为31张

## 4.3 找朋友（核心机制）

### 叫牌流程

1. **庄家叫牌**：庄家通过轮盘选择器指定一张牌（花色 + 点数 + 第几张，或大王/小王 + 第几张），如「第1张红桃 A」或「第3张大王」
3. **盟友认定**：游戏中第N个打出这张牌的玩家（N为指定的张数），自动成为庄家的秘密盟友
4. **队伍分配**：
   - 庄家 + 盟友 = 庄家方（2 人）
   - 其余 3 人 = 抓分方（3 人）

**叫牌范围**：
- 任意花色的任意点数（如红桃A、方片5等）
- 大王
- 小王
- **必须指定第几张**（第1张、第2张或第3张，N≤3）

**叫牌限制**：
- ❌ **不可以叫本轮场上已经亮过的牌**（叫庄、反庄时亮出的牌）
- ✅ 翻出来的底牌不算在内（底牌中的牌可以叫）
- ✅ 可以叫大王或小王（第1张、第2张或第3张）

**叫牌策略**：
- 叫第1张：最早打出者为盟友，盟友身份暴露最早
- 叫第2张：中间打出者为盟友，增加不确定性
- 叫第3张：最后打出者为盟友，盟友身份暴露最晚，战略性更强

### 响应式设计规范

| 设备类型 | 屏幕尺寸 | 轮盘尺寸 | 交互方式 |
|----------|----------|----------|----------|
| 手机 | < 768px | 280-320px | 单指滑动、点击 |
| 平板 | 768-1024px | 350-400px | 滑动、点击 |
| 电脑 | > 1024px | 400-450px | 鼠标拖动、点击 |

### 技术实现要点

1. **动画效果**
   - 轮盘旋转动画（300-500ms缓动）
   - 选中状态高亮闪烁
   - 切换轮盘时淡入淡出

2. **触摸优化**
   - 支持惯性滑动
   - 触觉反馈（震动）
   - 防止误触（确认弹窗）

3. **视觉反馈**
   - 当前选中项放大显示
   - 未选项半透明
   - 指针指向选中位置

4. **选择流程优化**
   - 选择花色后自动进入点数选择
   - 选择王后直接进入"第几张"选择（跳过点数选择）
   - 选择完"第几张"后进入确认界面
   - 大王和小王需要明显的图标标识

5. **三副牌特性**
   - 清晰显示"第1/2/3张"的战略意义
   - 提供每个选项的简要说明
   - 可以通过进度条显示当前选择步骤（1/3、2/3、3/3）

### 特殊情况

| 情况 | 结果 | 队形 |
|------|------|------|
| 叫的牌（第N张）在庄家手牌中 | 无法打出第N张，庄家独打 | 1 打 4 |
| 叫的牌（第N张）在底牌中 | 无法打出第N张，庄家独打 | 1 打 4 |
| 叫的牌（第N张）在他人手牌中 | 第N个打出该牌的玩家成为盟友 | 2 打 3 |
| 庄家持有该牌的部分但未达到N张 | 例如叫第3张红桃A，庄家有1张，其他玩家有2张，则第3个打出者为盟友 | 2 打 3 |

**示例说明**：
```
场景：庄家叫"第2张红桃A"
分布：庄家手中1张红桃A，玩家B手中1张，玩家D手中1张

结果：
- 第1个打出红桃A：可能是庄家、玩家B或玩家D（不是盟友）
- 第2个打出红桃A：该玩家成为盟友（无论是谁）
- 第3个打出红桃A：不影响（盟友已确定）
```

### 盟友识别时机

- 系统会实时统计指定牌被打出的次数
- 当第N张指定牌被打出时，打出者被识别为盟友
- 识别后盟友身份对所有人公开
- 识别前双方都不知道谁是盟友
- 如果游戏结束时仍未打出第N张，则判定为庄家独打（1打4）

**示例**：
```
庄家叫"第3张方片5"
- 有玩家打出方片5（第1次）→ 系统计数：1/3，盟友未确定
- 有玩家打出方片5（第2次）→ 系统计数：2/3，盟友未确定
- 有玩家打出方片5（第3次）→ 系统计数：3/3，该玩家确认为盟友！
```

## 测试场景

### 场景 4.1：庄家收取底牌
- **前置条件**：庄家已确定
- **测试步骤**：庄家收取底牌
- **预期结果**：庄家手牌从31张变为38张

### 场景 4.2：庄家扣回底牌
- **前置条件**：庄家已收取底牌
- **测试步骤**：庄家选择7张牌扣回
- **预期结果**：庄家手牌变为31张，底牌7张面朝下

### 场景 4.3：扣牌无限制
- **前置条件**：庄家手中有主牌、分牌
- **测试步骤**：尝试扣主牌、分牌到底牌
- **预期结果**：允许扣任意牌

### 场景 4.4：叫牌-选择花色牌
- **前置条件**：庄家已扣完底牌
- **测试步骤**：选择红桃 → 选择A → 选择第1张
- **预期结果**：叫牌为"第1张红桃A"

### 场景 4.5：叫牌-选择大王
- **前置条件**：庄家已扣完底牌
- **测试步骤**：选择大王 → 选择第3张
- **预期结果**：叫牌为"第3张大王"，跳过点数选择

### 场景 4.6：叫牌-选择小王
- **前置条件**：庄家已扣完底牌
- **测试步骤**：选择小王 → 选择第2张
- **预期结果**：叫牌为"第2张小王"，跳过点数选择

### 场景 4.7：不能叫已亮过的牌
- **前置条件**：抢庄时玩家亮出了红桃2
- **测试步骤**：庄家尝试叫"第1张红桃2"
- **预期结果**：不允许，提示该牌已被亮过

### 场景 4.8：可以叫底牌中翻出的牌
- **前置条件**：翻底牌定庄时翻出了方片5
- **测试步骤**：庄家尝试叫"第1张方片5"
- **预期结果**：允许叫该牌

### 场景 4.9：盟友识别-正常情况
- **前置条件**：庄家叫"第2张红桃A"
- **测试步骤**：第2个打出红桃A的玩家出牌
- **预期结果**：该玩家被识别为盟友，身份公开

### 场景 4.10：庄家独打-叫的牌在庄家手中
- **前置条件**：庄家手中有3张红桃A
- **测试步骤**：庄家叫"第1张红桃A"
- **预期结果**：庄家自己打出第1张红桃A时，判定为1打4

### 场景 4.11：庄家独打-叫的牌在底牌中
- **前置条件**：3张红桃A全部在底牌中
- **测试步骤**：庄家叫"第1张红桃A"
- **预期结果**：游戏结束时无人打出，判定为1打4

### 场景 4.12：盟友识别计数
- **前置条件**：庄家叫"第3张方片5"
- **测试步骤**：
  1. 玩家A打出方片5
  2. 玩家B打出方片5
  3. 玩家C打出方片5
- **预期结果**：前两次显示计数(1/3, 2/3)，第三次玩家C被确认为盟友

### 场景 4.13：庄家部分持有叫的牌
- **前置条件**：庄家叫"第3张红桃A"，庄家有1张，其他玩家有2张
- **测试步骤**：等待红桃A被打出3次
- **预期结果**：第3个打出红桃A的玩家（无论是谁）成为盟友

### 场景 4.14：轮盘响应式设计-手机
- **前置条件**：在手机上打开游戏（屏幕<768px）
- **测试步骤**：进入叫牌界面
- **预期结果**：轮盘尺寸为280-320px，支持单指滑动

### 场景 4.15：轮盘响应式设计-平板
- **前置条件**：在平板上打开游戏（屏幕768-1024px）
- **测试步骤**：进入叫牌界面
- **预期结果**：轮盘尺寸为350-400px

### 场景 4.16：轮盘响应式设计-电脑
- **前置条件**：在电脑上打开游戏（屏幕>1024px）
- **测试步骤**：进入叫牌界面
- **预期结果**：轮盘尺寸为400-450px，支持鼠标拖动
